Setup bersama untuk mencoba dengan aman

1. Buat environment Python dari root repository

Untuk baseline code-first dan alat konversi, gunakan PowerShell dan Python 3.13. Jalur declarative punya lock dan venv terpisah.

py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m pytest tests\unit tests\contract -q

Unit dan contract tests memakai fixture, tidak butuh Azure. Jangan menjalankan suite tests/live sebelum prasyarat serta akses disetujui.

2. Isi profil sendiri, jangan memakai konfigurasi operator

Copy-Item .\config\runtime.public.example.json .\config\runtime.local.json
# Isi profil lokal dengan identifier sandbox sebelum langkah berikut.
$env:DEMO_ENVIRONMENT_FILE = (Resolve-Path .\config\runtime.local.json).Path

Isi resource group, subscription, tenant, Foundry project, backing/MAF/Search, audience API, Logic Apps, dan scope Fabric sesuai template placeholder. Nilai profil runtime harus lengkap. Jangan memasukkan token, password, key, atau SAS ke profil. Restart server setelah mengubahnya; pada host Azure gunakan file profil non-publik dan konfigurasi host, bukan path laptop.

3. Siapkan resource dan izin sandbox

  1. Gunakan Azure CLI pada tenant/subscription sendiri. Untuk proses hosted, gunakan managed identity yang disetujui.
  2. Bekukan versi workflow sumber dan agent yang dipakai. Sediakan project Foundry, model deployment, dan koneksi tool.
  3. Siapkan backing API/MCP, isi data sintetis, lalu beri akses pada caller yang sesuai. Search, native knowledge retrieval, dan Fabric hanya relevan ketika rute yang menggunakannya diuji.
  4. Ikuti setup khusus pada workshop yang dipilih. Jangan memakai template deploy historis tanpa review scope, nama resource, dan identitas. Profil memilih resource; tidak memprovision, membuat izin, atau menghapus guard.

Nama field, setup, pola izin, dan contoh boleh dibagikan. File env, profil operasional, secret, token, dan URL bertanda tangan disimpan di luar Git. Lihat panduan lingkungan sendiri untuk konfigurasi host dan batas portabilitas.

Hitung per meter, jangan bandingkan tarif dari nama jalur

Logic Apps Consumption: biaya built-in action mengikuti eksekusi yang ditagih. Misal 100 run menambah 10 eksekusi action yang ditagih per run setelah jatah gratis terpakai. Hitungannya 100 × 10 × USD 0,000025 = USD 0,025 untuk meter itu saja. Ini ilustrasi hitung, bukan jumlah action hasil pengukuran MCP01 atau tagihan.

Sumber: Azure Retail Prices API, diperiksa 19 November 2026, SKU Consumption, Southeast Asia, meter Consumption Built-in Actions, USD per eksekusi berbayar. Harga kontrak, connector, penyimpanan, retry, model, dan layanan data bisa mengubah total.

MAF code-first dan YAML: hitung waktu host dan pemakaian layanan yang sama-sama dipanggil. Misalnya 100 pertanyaan yang masing-masing memanggil router dan satu specialist berarti 200 panggilan model pada asumsi tanpa retry; untuk menghitung USD, pakai token input/output dan tarif model terpilih. Tarif model dan host sandbox belum ditentukan di sini, bukan berarti nol. Logic Apps juga membayar model/tool bila memanggil layanan tersebut.

Logic Apps Standard memakai model hosting berbeda, bukan angka Consumption di atas. Cek meter Logic Apps, harga Logic Apps, dan harga Foundry untuk model, region, dan billing yang akan dipakai.

Kalau health hijau tapi data tidak ditemukan?

Health hanya memastikan server siap menerima HTTP. Lihat hasil bisnis dan bukti tool pada run yang sama. Jika rute harus blocked, itu bukan retrieval yang sukses. Catat kasus yang belum diuji, alih-alih menganggap satu run mewakili semua route.

Untuk membandingkan hasil lama, lihat satu run native di Designer. Untuk latihan lain, buka katalog prompt dan ekspektasi.
